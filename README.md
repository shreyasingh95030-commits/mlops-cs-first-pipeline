# Iris MLOps project

## Project layout

- `app/` — FastAPI application and shared MLflow configuration.
- `pipeline/` — model training, evaluation, registration, and champion alias update.
- `tests/` — API contract tests.
- `models/` — locally saved model artifact generated by training.
- `mlflow.db` — local MLflow tracking and model registry database.

The local database and generated model files are ignored by Git.

## Set up the environment

From the project root in PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

In VS Code, select `.venv\Scripts\python.exe` as the workspace interpreter.

## Run the training pipeline

Run this from the project root. It trains and evaluates the model, enforces a
minimum test accuracy of 0.90, logs the run to MLflow, registers the model,
and assigns the `champion` alias.

```powershell
python -m pipeline.train
```

The pipeline creates `mlflow.db` and `models\iris_model.joblib`.

## Start the API

Train the model before starting the API so that the registered `champion`
model is available.

```powershell
python -m uvicorn app.main:app --reload
```

- API health: <http://127.0.0.1:8000/health>
- Interactive API docs: <http://127.0.0.1:8000/docs>
- Prediction endpoint: `POST http://127.0.0.1:8000/predict`

Example request body:

```json
{
  "sepal_length": 5.1,
  "sepal_width": 3.5,
  "petal_length": 1.4,
  "petal_width": 0.2
}
```

## Run tests

Train once first, then run:

```powershell
python -m pytest
```

To use a remote MLflow tracking server, set `MLFLOW_TRACKING_URI` before
running either the training pipeline or the API. Both use the same setting.
